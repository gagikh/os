# Glossary · Տերմինների բառարան

Embedded Linux դասընթացի տերմինները՝ այբբենական կարգով։ Ամեն տերմինի վերջում նշված է այն օրը, երբ այն ներմուծվում է, `(Day N)`. այնտեղ կգտնես ամբողջական բացատրությունը և նկարը, եթե կա։ Հրամանների համար տե՛ս [COMMANDS.md](COMMANDS.md), ֆունկցիաների համար՝ [API.md](API.md)։

**Architecture (aarch64, x86_64)** — CPU-ի հրամանների համակարգը։ PC-ների մեծ մասը `x86_64` են, մեր երեք բորդը (Jetson, Raspberry Pi 4/5, i.MX8)՝ `aarch64` (64-bit ARM)։ Մեկի համար հավաքված ծրագիրը մյուսի վրա չի աշխատում։ *(Day 1)*

**Cross build (cross-compilation)** — Ծրագիրը հավաքվում է մի architecture-ի վրա (PC, `x86_64`) մյուսի համար (բորդ, `aarch64`)՝ **cross compiler**-ով, օրինակ `aarch64-linux-gnu-g++`։ *(Day 1)*

**Device tree** — Տեքստային նկարագրություն, որն ասում է kernel-ին, թե ինչ hardware կա բորդի վրա։ PC-ն այն չունի, ARM բորդերն ունեն։ Այսօր միայն կկարդանք բորդի անունը `/proc/device-tree/model`-ից, մանրամասները Օր 2-ում են։ *(Day 1)*

**Distribution (դիստրիբուտիվ)** — Kernel-ը՝ գրադարանների, ծրագրերի և package manager-ի հետ միասին, պատրաստ տեղադրման համար։ Օրինակներ՝ Ubuntu, Debian, Raspberry Pi OS։ Jetson-ի վրա NVIDIA-ի Ubuntu-ն է (L4T), Raspberry Pi-ի վրա՝ Raspberry Pi OS-ը։ *(Day 1)*

**ELF** — Linux-ի կատարվող ֆայլերի ձևաչափը։ `file` հրամանը ELF-ից կարդում է, թե որ architecture-ի համար է ծրագիրը։ *(Day 1)*

**Exit status** — Թիվ, որը ծրագիրը վերադարձնում է ավարտվելիս. `0`՝ հաջող, այլ թիվ՝ սխալ։ Վերջին հրամանի exit status-ը `$?`-ն է։ *(Day 1)*

**Group** — Օգտատերերի խումբ։ Բորդի վրա սարքերի ֆայլերը (`/dev/ttyUSB0`, `/dev/i2c-1`) պատկանում են որոշակի group-ի (`dialout`, `i2c`), և դրանց հետ աշխատելու համար օգտատերը պետք է լինի այդ group-ում։ *(Day 1)*

**Headless** — Առանց մոնիտորի և ստեղնաշարի աշխատող սարք։ Embedded բորդերի մեծ մասն այդպես են աշխատում, և նրանց հետ աշխատում ենք PC-ից՝ ցանցով կամ serial կապով։ *(Day 1)*

**Linux kernel (միջուկ)** — Օպերացիոն համակարգի այն մասը, որն ուղիղ աշխատում է hardware-ի հետ. բաշխում է CPU-ի ժամանակը process-ների միջև, կառավարում է հիշողությունը, ֆայլային համակարգերը, ցանցը և driver-ների միջոցով սարքերը։ Բառի խիստ իմաստով «Linux»-ը միայն kernel-ն է։ *(Day 1)*

**Native build** — Ծրագիրը հավաքվում է նույն մեքենայի վրա, որտեղ աշխատելու է։ *(Day 1)*

**Package manager** — Ծրագիր, որը ներբեռնում և տեղադրում է պատրաստի ծրագրեր (packages)՝ իրենց կախվածություններով։ Ubuntu-ում, Debian-ում և Raspberry Pi OS-ում դա `apt`-ն է։ *(Day 1)*

**Path (ճանապարհ)** — Ֆայլի հասցեն ծառում։ **Absolute** path-ը սկսվում է `/`-ով (`/home/lab/day01`), **relative**-ը հաշվվում է ընթացիկ թղթապանակից (`day01/hello.c`)։ `~`-ը օգտատիրոջ home թղթապանակն է, `.`-ը՝ ընթացիկը, `..`-ը՝ վերևինը։ *(Day 1)*

**Permission (իրավունք)** — Ֆայլի վրա թույլատրված գործողությունները. `r` (կարդալ), `w` (գրել), `x` (կատարել), առանձին owner-ի, group-ի և մնացած բոլորի համար։ *(Day 1)*

**Process** — Աշխատող ծրագիր։ Ունի իր համարը՝ **PID**-ը, իր հիշողությունը և իր owner-ը։ Նույն ծրագիրը երկու անգամ գործարկելով ստանում ենք երկու process։ *(Day 1)*

**Prompt** — Shell-ի տողը, որը սպասում է հրամանի. `lab@jetson:~$`։ Ցույց է տալիս օգտատիրոջը (`lab`), համակարգչի անունը (`jetson`), ընթացիկ թղթապանակը (`~`) և իրավունքները (`$`՝ սովորական օգտատեր, `#`՝ `root`)։ *(Day 1)*

**Root** — Երկու իմաստ ունի. ֆայլային ծառի սկիզբը `/`, և գերօգտատերը `root`, որին ամեն ինչ թույլատրված է։ *(Day 1)*

**Serial console** — Shell կամ boot-ի հաղորդագրություններ UART-ի միջոցով, սովորաբար USB-to-UART մալուխով։ Աշխատում է ցանցից անկախ, boot-ի առաջին վայրկյանից, այդ պատճառով այն «փրկության» ճանապարհն է, երբ SSH-ը չի աշխատում։ *(Day 1)*

**Shell** — Ծրագիր, որը կարդում է մեր գրած հրամանները և կատարում դրանք։ Linux-ում ամենատարածվածը `bash`-ն է։ **Terminal**-ը պատուհանն է, որում shell-ն աշխատում է։ *(Day 1)*

**SSH (Secure Shell)** — Արձանագրություն, որով PC-ից ցանցով բացում ենք shell բորդի վրա։ Կապը կոդավորված է։ Բորդի վրա աշխատում է `sshd` server-ը (port 22), PC-ից միանում ենք `ssh user@IP` հրամանով։ *(Day 1)*

**`sudo`** — Մեկ հրամանը կատարում է `root`-ի իրավունքներով։ Պահանջում է քո գաղտնաբառը։ *(Day 1)*

**System call** — Ծրագրի խնդրանքը kernel-ին. `open`, `read`, `write`, `fork` և այլն։ C-ի `printf`-ը, Python-ի `print`-ը վերջում կանչում են `write` system call-ը։ *(Day 1)*

**User space և kernel space** — Սովորական ծրագրերն աշխատում են user space-ում և hardware-ին ուղիղ դիմել չեն կարող։ Ամեն ինչ, ինչ պահանջում է hardware (ֆայլ կարդալ, ցանցով տվյալ ուղարկել, GPIO փոխել), անցնում է kernel-ով՝ **system call**-ի միջոցով։ *(Day 1)*
